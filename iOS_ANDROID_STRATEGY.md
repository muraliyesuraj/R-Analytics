# iOS & Android Development Strategy

**Decision**: Develop both iOS and Android **simultaneously** (recommended for React Native).

---

## Why Both Together?

| Consideration | Sequential (Android → iOS) | Simultaneous |
|---|---|---|
| **Code sharing** | 90%+ identical, but developed twice | 90%+ written once, deployed to both |
| **Launch date** | 8-10 weeks (Android 6w + iOS 6w) | ~6 weeks (both in parallel) |
| **Testing overhead** | Simpler, focused per platform | Slightly more complex, but parallelizable |
| **Time to first users** | Android only for 2 weeks | All users day 1 |
| **Support burden** | Handle "why isn't it on iOS?" complaints | Launch together, manage together |
| **React Native ROI** | Underutilized (write once, deploy twice) | Maximized (true write-once-deploy-anywhere) |

**Bottom line**: React Native's entire value prop is "write once, run on both platforms." Sequential defeats that.

---

## Development Timeline (Weeks)

```
Week 1-2: Setup (Expo project, types, wheel data)
├─ Both: Same codebase
└─ Minimal platform-specific code

Week 2-4: Features (felt, spin logging, metrics)
├─ Both: 95% shared code
├─ iOS: Test on Simulator + occasional device checks
└─ Android: Test on Emulator + occasional device checks

Week 5: QA & Testing
├─ iOS: iPhone SE, 12, real device
├─ Android: Pixel 4, Galaxy S21, real device
├─ Cross-platform: Feature parity, performance
└─ Fix bugs found on either platform (single fix applies to both)

Week 6: App Store Launch
├─ Build both: eas build --platform ios && eas build --platform android
├─ Submit both: eas submit (both platforms)
├─ Monitor: Apple (24-48h), Google (2-4h)
└─ Launch: Both stores announce together
```

- [ ] Safe Area handling (notches, Dynamic Island)

- [ ] System navigation buttons vs gesture nav

- [ ] Tablet layouts (if targeting 10"+)

### Shared (Both Platforms)
- [ ] Touch target sizes (>= 44×44 points)
- [ ] Font rendering (system fonts work best)
- [ ] Color accuracy (test on real devices)
- [ ] Scrolling performance (FlatList, virtualization)
- [ ] Dark mode (if implemented)
- [ ] Landscape orientation (if needed)

## Code Structure (99% Shared)

```
src/
├── types/           # 100% shared
├── data/            # 100% shared (WHEEL_PROPERTIES)
├── store/           # 100% shared (Zustand state)
├── utils/           # 100% shared (calculations, storage)
├── components/      # 95% shared (React Native components work on both)
└── screens/         # 95% shared (navigation, layouts mostly identical)

ios/                 # Auto-generated by Expo (ignore in development)
android/             # Auto-generated by Expo (ignore in development)
```

**Platform-specific code** (rare, in `components/`):
```typescript
// Platform-specific styling only when absolutely needed
import { Platform } from 'react-native';

const styles = StyleSheet.create({
  container: {
    paddingTop: Platform.OS === 'ios' ? 10 : 0,
  },
});
```

## Build & Submit Strategy

### Build Both Simultaneously
```bash
# Builds iOS and Android in parallel (takes ~20-30 min each)
eas build
# (No --platform flag = build both)
```

Or build one at a time:
```bash
eas build --platform ios   # Takes ~20-25 min
eas build --platform android  # Takes ~25-30 min
```

### Submit Both Simultaneously
```bash
# Submit both at the same time
eas submit --platform ios &
eas submit --platform android &
wait
```

**Timeline after submission**:
- iOS: 24-48 hours (Apple reviews every app manually)
- Android: 2-4 hours (Google uses automated + spot checks)
- **Expected**: Both live within 48 hours, usually same day

## Quality Assurance Approach

### Phase 1: Daily Development (Weeks 2-4)
- **Target**: Run on iOS Simulator + Android Emulator daily
- **Effort**: 5 min each, catch obvious bugs
- **Devices**: Only simulators/emulators

### Phase 2: Continuous Testing (Weeks 3-5)
- **Target**: Real device once per week
- **Effort**: 15 min, test actual hardware feel
- **Devices**: 1 real iPhone, 1 real Android (borrow if needed)

### Phase 3: Intensive QA (Week 5)
- **Target**: Test matrix (multiple devices, screen sizes)
- **Effort**: 4-6 hours dedicated QA day
- **Devices**: Simulators + real devices, multiple screen sizes

### Phase 4: Pre-Launch (Day 6)
- **Target**: Final smoke test on production builds
- **Effort**: 2 hours (simulate what users will download)
- **Devices**: Real devices only, production builds

## Common Issues & Fixes

### "My app looks different on iOS vs Android"
**Solution**: Use `Platform.OS` sparingly. Most issues are SafeArea, not code.
```typescript
import { SafeAreaView } from 'react-native-safe-area-context';
// Wrap screens in SafeAreaView—handles both platforms
```

### "Back button doesn't work on Android"
**Solution**: React Navigation handles this automatically. No code needed.

### "Font is bigger on Android"
**Solution**: Normal (Android has higher DPI). Use `allowFontScaling={false}` if needed.

### "Metrics are different on each platform"
**Solution**: Would indicate a code bug (shouldn't happen). Run same code on both → same metrics.

### "Status bar is hidden on one platform"
**Solution**: Check `app.json` `statusBarConfig`. Expo handles it.

## Why NOT Sequential?

### "Android first, iOS later"
- ❌ React Native code is 90%+ identical → writing it twice wastes 50% effort
- ❌ iOS launch delayed 3-4 weeks (opportunity cost, market timing)
- ❌ Bugs fixed on Android often need re-fixing on iOS
- ❌ Users on one platform feel abandoned

### "iOS first, Android later"
- ❌ Same problems as above
- ❌ Android market is larger in many regions (delayed revenue)
- ❌ iOS-specific bugs may not surface until Android dev

### "Both together"
- ✅ Efficient (write once, deploy twice)
- ✅ Simultaneous launch (no second-class citizen platform)
- ✅ Shared QA process (same tests, both platforms)
- ✅ Maximizes React Native's value prop

---

## Success Criteria (Both Platforms)

- ✅ Same features on iOS and Android
- ✅ Same calculations (12 metrics identical)
- ✅ Same data persistence (AsyncStorage works both)
- ✅ Same performance (no lag on either platform)
- ✅ Same UX (touch feels natural on both)
- ✅ No platform-specific crashes
- ✅ Both app stores accept & publish

## Decision Summary

| Approach | Timeline | Effort | Result |
|---|---|---|---|
| Android → iOS (sequential) | 8-10 weeks | High (duplicate work) | One platform at a time |
| **Both together** | **~6 weeks** | **Moderate (parallelizable)** | **All users day 1** |

**We're going with both together.** Phase 0 setup is identical, development is 95% shared code, testing is parallelizable, and launch is synchronized.
